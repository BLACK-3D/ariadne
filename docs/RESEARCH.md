# Local AI runtime decisions

Primary sources checked on 2026-10-27. These are engineering recommendations and upstream facts, not a claim that every optional component has been installed or tested in this repository.

## Inference and model choice

Use **Ollama with `qwen3:4b`** as the initial, configurable inference backend. Ollama's official artifact is approximately 2.5 GB, uses Q4_K_M quantization, advertises tool support, and carries Apache-2.0 model licensing. This is model storage size, not a guarantee of required RAM, speed, reasoning quality, or hardware compatibility. Record the full local artifact digest after provisioning. An 8B model is an upgrade candidate after measuring quality and latency on the actual host. [Official model artifact](https://ollama.com/library/qwen3:4b), [publisher's 4B GGUF model card](https://huggingface.co/Qwen/Qwen3-4B-GGUF), [publisher's 8B model card](https://huggingface.co/Qwen/Qwen3-8B).

Ollama's native `POST /api/chat` accepts JSON-schema function tools. The application must validate and execute returned calls, append tool results to the conversation, and request another model response. Tool calling does not give the model direct authority over the computer. Bound the loop, validate arguments, limit output, and stop on cancellation or failure. [Official tool-calling documentation](https://docs.ollama.com/capabilities/tool-calling).

For routine requests, disable thinking, cap generated tokens, serialize inference on a small host, and keep only the necessary context. These are testable efficiency choices, not measured savings. The API reports prompt/output token counts and duration fields that can support later measurements. [Chat API](https://docs.ollama.com/api/chat).

Set `OLLAMA_NO_CLOUD=1` and restart Ollama to disable its cloud models and web search. Keep its port private to the application network. Ollama normally binds to loopback. Its API supports configurable model retention; short retention reduces idle memory residence but increases cold-start work. Parallel requests multiply context memory, so start with one inference at a time and one loaded model. [Ollama configuration and local-only mode](https://docs.ollama.com/faq).

**llama.cpp** is an alternative when appliance packaging or direct control of a pinned GGUF binary becomes valuable. Its MIT-licensed C/C++ runtime provides CPU/GPU quantized inference; its server supports compatible chat routes, function calling, and schema-constrained JSON. Treat it as an alternative adapter, not a second always-running inference dependency. Chat templates and tool parsing still need compatibility tests for the exact model and release. [Project](https://github.com/ggml-org/llama.cpp), [server documentation](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md).

## Voice is an optional local subsystem

**whisper.cpp** is a practical speech-to-text candidate: MIT-licensed, CPU-capable, quantization support, and Windows/Linux support. Its upstream table estimates the base model at 142 MiB on disk and approximately 388 MB memory, excluding the rest of the application and operating system. Those estimates do not establish real-time transcription on this machine. The project includes offline assistant and HTTP server examples. Capture audio locally and submit it to the local server; browser speech recognition must not be represented as an offline guarantee. [Project and resource estimates](https://github.com/ggml-org/whisper.cpp), [HTTP server](https://github.com/ggml-org/whisper.cpp/tree/master/examples/server).

The current stable [v1.9.5 release](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.5) links to official binary build **b5454** at the same source commit. Its [Windows x64 CPU ZIP](https://github.com/ggml-org/whisper.cpp/releases/download/b5454/whisper-bin-x64.zip) is approximately 8.52 MB. The [published asset inventory](https://github.com/ggml-org/whisper.cpp/releases/expanded_assets/b5454) reports SHA-256 `6ba69e3482d7826214f90a6a9c84ca07782aec1e1d0c6a7c30c994fd5d816ccb`. Keep the DLLs beside `whisper-cli.exe` when extracting it. This binary build is marked prerelease on GitHub, although the stable release explicitly references it.

The project's [official model download script](https://github.com/ggml-org/whisper.cpp/blob/v1.9.5/models/download-ggml-model.sh) uses the `ggerganov/whisper.cpp` Hugging Face repository. Pin its checked revision **`5359861c739e955e79d9a303bcbc70fb988958b1`** and retrieve [ggml-base.en.bin](https://huggingface.co/ggerganov/whisper.cpp/resolve/5359861c739e955e79d9a303bcbc70fb988958b1/ggml-base.en.bin). Its [file metadata](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-base.en.bin) publishes SHA-256 `a03779c86df3323075f5e796cb2ce5029f00ec8869eee3fdfb897afe36c6d002`; the [LFS pointer](https://huggingface.co/ggerganov/whisper.cpp/raw/main/ggml-base.en.bin) specifies **147,964,211 bytes**. Verify both size and hash before use. This is the English-only base model; multilingual input needs a corresponding multilingual model and separate validation.

**Piper** can provide local speech synthesis, but the maintained project is now `OHF-Voice/piper1-gpl`, with GPL-3.0 licensing. The old `rhasspy/piper` repository is archived. Review runtime distribution obligations and each chosen voice's card before bundling. For example, the Lessac medium voice links to separate dataset terms; a repository-level label does not replace that review. Keep synthesis behind an optional local HTTP adapter. The current API documents `POST /synthesize` returning WAV audio. [Maintained project](https://github.com/OHF-Voice/piper1-gpl), [archived project](https://github.com/rhasspy/piper), [voice card](https://huggingface.co/rhasspy/piper-voices/blob/main/en/en_US/lessac/medium/MODEL_CARD), [HTTP API](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/API_HTTP.md).

## Provision once, then operate offline

### Pinned Windows portable runtime

The official Windows documentation supports the standalone ZIP and `ollama serve`; an installer or administrator rights are unnecessary for this application-local approach. Extract into a dedicated `runtime/ollama/` directory. Set process-local `OLLAMA_MODELS` to the project's `data/models/`, `OLLAMA_HOST=127.0.0.1:11434`, and `OLLAMA_NO_CLOUD=1`. Keep temporary files and logs on C: as well; E: is excluded by the owner's instruction. [Official Windows documentation](https://docs.ollama.com/windows).

The checked release is **v0.40.12**. Its official [portable x64 ZIP](https://github.com/ollama/ollama/releases/download/v0.40.12/ollama-windows-amd64.zip) is approximately **1.49 GB**. The SHA-256 published on [GitHub's release asset inventory](https://github.com/ollama/ollama/releases/expanded_assets/v0.40.12) is `21814944f3e50d3f07b6bb3af75baddb96f59e91353c332ac9c5063b3bfd1041`. Verify the archive hash before extraction. The release's verified commit signature is not evidence that an extracted executable has a valid Windows Authenticode signature; inspect that separately before execution. [Pinned release](https://github.com/ollama/ollama/releases/tag/v0.40.12).

For the optional production WSGI server, **`waitress==3.0.2`** is the current published release checked here; it supports Windows and Python 3.9+ without third-party runtime dependencies. The universal wheel is approximately 56.2 kB, with SHA-256 `c56d67fd6e87c2ee598b76abdd4e96cfad1f24cacdea5078d382b1f9d7b5ed2e`. Pin the version and wheel hash when creating an offline dependency bundle. [PyPI release and hashes](https://pypi.org/project/waitress/3.0.2/), [maintainer release](https://github.com/Pylons/waitress/releases/tag/v3.0.2).

Before disconnecting, acquire the runtime, model, application files, container images if used, and optional speech binaries/models. Save versions, hashes/digests, model cards, and licenses with the deployment bundle. A configured model name alone does not make the model available offline. Ollama's installed-model endpoint reports model size, digest, and quantization details for an inventory. [Installed-model API](https://docs.ollama.com/api/tags).

For optional Hugging Face downloads, use publisher-controlled repositories, pin a full revision, and download only necessary files. `HF_HUB_OFFLINE=1` prevents Hub HTTP calls and uses cached files; a missing cache fails instead of downloading. Acquire files in a provisioning step, not inside a scheduled task. [Revision-pinned downloads](https://huggingface.co/docs/huggingface_hub/guides/download), [offline configuration](https://huggingface.co/docs/huggingface_hub/package_reference/environment_variables).

Do not automatically install arbitrary repository code or enable `trust_remote_code` to add a capability. Prefer reviewed artifacts and supported data formats; treat model parsers as software that also needs maintenance. Hugging Face explicitly states its pickle scanning is not a complete guarantee and that Python packages are not actively audited by that scanner. Popularity and a clean scan alone do not establish safety. [Hub pickle security guidance](https://huggingface.co/docs/hub/security-pickle).

## Useful autonomy and honest acceptance

The implementable target is a local assistant that can run bounded tasks, manage local knowledge and files, keep a durable queue, produce artifacts, and call explicitly configured integrations. It can draft business plans and create software artifacts. Actual business registration, spending, external publication, communications, and device control require integrations, credentials, and a defined authority policy. General intelligence, universal competence, and movie-level Jarvis behavior are not established acceptance criteria or deliverable guarantees.

Use SQLite and local search first. Add embeddings, large models, additional services, or always-on voice only when a measured acceptance failure justifies their storage, power, memory, and maintenance costs. Record latency, generated tokens, task success, and idle/inference wall power before claiming operating-cost savings.

Validate an appliance with the WAN disconnected: cold restart, authenticate from a second LAN client, chat with the provisioned model, execute a local task, retrieve a saved document, and inspect durable history. Separately test interrupted jobs after process failure and verify that externally visible actions are not replayed silently. Keep a backup of persistent state and a recoverable runtime/model bundle. A generator also needs to power the server and local networking; model inference cannot supply fresh internet data while the WAN is unavailable.
