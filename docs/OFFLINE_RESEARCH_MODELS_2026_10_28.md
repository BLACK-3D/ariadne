# Offline model and inference research — 2026-10-28

Research only: no model, runtime, account, service, or running Ariadne configuration was changed. Sources below are the developers' own repositories, model cards, release notes, and documentation. Hardware supplied by the local inventory: Windows, Core i9-9900K (8 cores / 16 threads), about 64 GiB RAM, RTX 5060 Ti reporting 16,311 MiB VRAM, NVIDIA driver 617.14. No access to E: was needed.

## Practical conclusion

The most useful next model comparison is **Qwen3.5-9B versus Gemma 4 12B**, with **Qwen3.5-4B / MiniCPM5-2B** as smaller task-specific options. **Nemotron 3.5 Bolt E4B** is a particularly relevant new conversational/tool-use experiment. Keep a larger model for explicitly requested difficult work only after measuring its performance on this PC. These are priorities for qualification, not measured claims that any candidate beats Ariadne's installed Qwen3:8b.

Local inference can continue without an internet connection once the complete runtime, model, tokenizer, chat template, projector/codec where required, and dependency set are downloaded. Hosted search, current news, SaaS tools, cloud model tags, remote package installation, and remote URLs in sample prompts remain online operations. Available local weights do not make a tool or agent sandbox safe.

## Larger models investigated and deferred

- **Qwen3-Coder-Next**, February 2026: 80B stored parameters / 3B active, native 256K and non-thinking; Apache-2.0. The active-parameter count describes per-token work, not weight storage. The theoretical four-bit floor is 40 GB before overhead: possible only as a carefully measured host-memory/offload project on this PC, not a 3B-size GPU download. [Official card](https://huggingface.co/Qwen/Qwen3-Coder-Next).
- **Muse Glimmer 30B**, August 2026: Apache-2.0 text/image agent model with official 17 GB K-quant option plus perception and optional drafter; exceeds this GPU's memory before cache. Attractive future offload comparison, lower immediate priority. [Official card](https://huggingface.co/meta-models/Muse-Glimmer-30B), [official package guide](https://dev.meta.ai/docs/muse-glimmer/get-the-model).
- **Qwen3.8-Flash-Next** is an experimental preview with 125B parameters / 6B active **plus 51B n-gram embeddings and 4B MTP**, and a Qwen Community license. Even the idealized four-bit total exceeds the host's 64 GiB before runtime overhead. “Flash” does not make the full model a practical everyday fit here. [Official card](https://huggingface.co/Qwen/Qwen3.8-Flash-Next).

## Runtime findings and qualification gate

**Ollama 0.40.12** (Oct27) is already the Ariadne baseline in the delivery record. Its platform-specific release limitation above is material; a supported model architecture on one backend is not support on all backends. Use explicit local model identifiers and pinned digests, not `*-cloud` tags. [Official release](https://github.com/ollama/ollama/releases/tag/v0.40.12).

**llama.cpp 0.8.0** (Oct28, release commit `8642541`) is the current semantic release checked. It adds the LFM3 family, experimental streaming audio/realtime/TTS, host-resident MoE cache work, and tool-calling improvements. Its MIT code license does not change any loaded model's license. CUDA and CPU/Vulkan backends make it a useful portable candidate; this is an option to qualify alongside the existing runtime, not an instruction to replace production with a release from today. [Release](https://github.com/ggml-org/llama.cpp/releases/tag/v0.8.0), [repository/backends](https://github.com/ggml-org/llama.cpp).

The maintained project's security page includes 2026 GGUF-parser overflow and RPC RCE advisories. Downloading data-only GGUF/projector files does not remove native parser risk. Verify official origin, exact revision/hash, matching model/projector, applicable fixes, and retain loopback-only serving with no RPC exposure. This research does not certify any release free of vulnerabilities. [Maintainer advisories](https://github.com/ggml-org/llama.cpp/security/advisories).

Before promotion: disconnect network and cold-start; test tool-call schema fidelity, approval/rejection persistence, prompt injection, bounded outputs/cancellation, knowledge citations, real image/audio cases where supported, and exact artifact checks. Record first-token latency, completed-task latency, peak RAM/VRAM, idle behavior, and energy per successful task if measured. Benchmark identical task sets and context budgets against installed Qwen3:8b. Keep failed cases. On-demand loading and small specialist routing are sensible designs to evaluate; no percentage cost/energy saving has been measured here.
