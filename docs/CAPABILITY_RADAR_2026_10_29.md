# Ariadne capability radar · 29 October 2026

**Research addendum: business operations, trading research and Jarvis-like controls.**

This scan examines **49 detailed repository/model candidates**, three adjacent/discovery-only control projects, eight additional GitHub search leads and classic FinRL as predecessor evidence. It covers GitHub, publisher Hugging Face model cards, exact license files, official release metadata and product documentation. It is a broad capability survey, not an exhaustive crawl of every repository or a source-code security certification. The machine-readable inventory records scope, unknowns and primary sources. **Nothing in this report is newly installed or connected.**

The recommended expansion is to connect reliable business records, reproducible market research and local device awareness to Ariadne's existing engine. Keep exact calculations, schedules and checks deterministic. Models should interpret, propose and explain; scoped adapters and verified receipts should govern actions. These priorities are engineering judgments based on incremental value and expected maintenance, not measured savings or trading returns.

## Integration design and operating burden

Use a small adapter per selected system: **source record → dated/hash-bound local snapshot → fixed calculation/check → proposal → approved write → receipt and reconciliation**. Untrusted web text, files, skills and model output cannot grant authority. A new service should reuse Ariadne's existing pause, approval and interrupted/uncertain-action handling instead of introducing a second permission system.

Historical analytics and existing fixed procedures need no new resident model. A full ERP, Home Assistant VM/container or durable service platform adds storage, updates, backups and powered hardware; these are qualitative maintenance assessments. New models add assets and temporary inference load. Brokerage feeds, exchange data, some CLI plans and enterprise terms can add recurring fees. No benchmark, energy measurement, subscription purchase or monetary saving is claimed by this research.

Before promoting a candidate, pin its exact source/binary/model assets and licenses; qualify cold offline startup and a real task on the target PC; measure peak RAM/VRAM, latency and disk use; test authorization, file/network boundaries, interruption and no-replay behavior; and retain a working rollback. Paper and live execution need their own scope, data freshness and reconciliation tests. Repository popularity, an archive flag or a signed commit does not certify a package's safety.

## Repository update reporting

Today's scan is completed now. Future automatic checks have not been enabled by this report. If selected, the efficient recurring design is a **bounded release/security/license delta check against this shortlist**, with dated caches and unchanged-result reuse, plus a less frequent broad discovery pass. An offline morning can present the last checked snapshot and its age; it cannot truthfully claim a fresh Internet scan. Never auto-install or execute a newly discovered repository.
