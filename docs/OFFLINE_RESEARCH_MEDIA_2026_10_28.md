# Offline speech, perception, and media research — 2026-10-28

Research only. These candidates were checked against publisher repositories, model cards, releases, and licenses; none was installed or enabled for this survey. Target: Ariadne on Windows with an RTX 5060 Ti and 16 GB VRAM. Existing whisper.cpp base.en, Windows SAPI, and RapidOCR remain the comparison baseline. Hardware suitability below is an engineering assessment unless a publisher measurement is explicitly identified. No measurements on this PC were taken.

The strongest next addition is a bounded local speech service: streaming recognition, interruption/endpointing, improved synthesis, and meeting transcripts with anonymous speaker labels. A separate image worker offers a larger new creative capability. Run heavy workers on demand and serialize GPU jobs; loading every model together would undermine the box's reliability and energy goals.

## Additional capabilities worth tracking

- **Full-duplex local conversation:** NVIDIA NemotronLabs VoiceChat 11B, released **2026-08-03**, combines speech understanding/output and tool calls with interruption handling. OpenMDW-1.1 weights. NeMo-Speech.cpp 0.2.0 exposes a source-built CUDA-only route, explicitly absent from prebuilt release archives. Canonical model documentation lists Linux and large NVIDIA GPUs. It is an experimental frontier, not a verified 16 GB Windows replacement for Ariadne's bounded model/tool loop. [Model](https://huggingface.co/nvidia/NVIDIA-NemotronLabs-VoiceChat-11B), [runtime release details](https://github.com/NVIDIA/NeMo-Speech.cpp/releases/tag/v0.2.0).
- **Voice activity detection:** Silero VAD **6.2.3**, released **2026-09-23**, MIT repository with local ONNX/PyTorch options. Gate costly ASR behind actual speech, retain short pre-roll so starts are not clipped, and measure false triggers in generator/fan/background noise. VAD means speech activity, not wake-word intent. [6.2.3 release](https://github.com/snakers4/silero-vad/releases/tag/v6.2.3), [source](https://github.com/snakers4/silero-vad).
- **Batch meeting processing alternative:** pyannote.audio **4.0.7**, **2026-06-30**, with `speaker-diarization-community-1`: MIT code, CC-BY-4.0 pipeline, initial Hugging Face gating/account acceptance. Official card documents full offline loading after cloning. Set `PYANNOTE_METRICS_ENABLED=0` to disable metrics; never select hosted `precision-2` for an offline path. Heavier Torch/FFmpeg dependencies than the native speech route. [Releases](https://github.com/pyannote/pyannote-audio/releases), [community model and offline guide](https://huggingface.co/pyannote/speaker-diarization-community-1).
- **Local camera events and searchable recordings:** Frigate latest stable resolves to **0.18.2**, **2026-10-15**, with security fixes. A mature separate appliance option, but this Windows workspace has no Docker. Camera credentials, storage retention, model licenses and CPU/GPU allocation need a separate owner setup. Do not auto-enable hosted GenAI providers or expose its ports. It is not an immediate Ariadne dependency. [Latest release](https://github.com/blakeblackshear/frigate/releases/tag/v0.18.2), [project](https://github.com/blakeblackshear/frigate).
- **Object cutout and visual tracking:** SAM 3.1 Object Multiplex announced **2026-03-27**; SAM 3 handles text/point/box-driven object segmentation and tracking in images and video. Official weights are gated and have a custom license; native Windows and memory budgets remain unqualified. Track for product-photo editing and object selection, rather than treating OCR as image understanding. [Official project](https://github.com/facebookresearch/sam3), [model](https://huggingface.co/facebook/sam3).

## Important exclusions and corrections

- **Latest is not automatically suitable for business:** Qwen-Image-2.1 and 2.1-Turbo official cards use `qwen-research`; they must not inherit the Apache license of older Qwen-Image releases. Keep them out of the general business bundle until the exact terms permit the intended use. [2.1](https://huggingface.co/Qwen/Qwen-Image-2.1), [Turbo](https://huggingface.co/Qwen/Qwen-Image-2.1-Turbo).
- **Wake-word license trap:** openWakeWord code is Apache-2.0 but its included pretrained models are CC-BY-NC-SA-4.0. A commercially deployable Ariadne box cannot simply bundle those weights under the code license. A custom reviewed model or another explicitly licensed checkpoint is required. [Upstream license section](https://github.com/dscripka/openWakeWord#license).
- **Avoid duplicate ASR stacks:** Moonshine, sherpa, Qwen and NVIDIA are competing integration routes. Benchmark a small shortlist, select a default, and leave alternatives optional. No energy or cost savings have been measured here.
- **Native performance is useful, not sufficient evidence:** release signatures/checksums and model cards establish provenance, not freedom from vulnerabilities. Parse all audio/images/video in bounded workers. Do not execute repository setup snippets or unreviewed custom nodes automatically.

## Offline acceptance before activation

Provision exact versions and model revisions with hashes and notices inside Yikes. Package transitive runtime DLLs, tokenizers, pronunciation data and codecs as well as weights. Choose local paths with no automatic model fallback/download; block internet during the acceptance run. Verify cold start without network, selected-file input, resource bounds, cancellation, safe artifact output and redacted failures. Check on the actual PC that speech/synthesis can coexist with the LLM, and that the GPU queue unloads it before heavier image/video jobs. Test the real microphone, speaker echo and generator noise before claiming hands-free robustness. Microphone/camera capture remains explicit and visible, and tool actions keep Ariadne's existing approval rules.
