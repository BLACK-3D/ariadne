# Ariadne interface: Threadline

Threadline presents Ariadne as a local operating environment. Its charcoal and olive surfaces, restrained phosphor accents and vector lattice are delivered entirely from this installation, with system fonts and no remote visual assets.

## Direct the work

The home surface puts three things together: Ariadne's observed state, your next directive, and the local readout. The input stays visible on ordinary laptop layouts. On narrow screens it comes first, with navigation along the bottom. Service desk, Venture Lab, Workflows and Daily brief have direct workspace routes; opening one does not start a mission.

**Continuity** opens a mission already known to this browser: the selected dossier, otherwise a running or queued mission, otherwise the latest loaded record. It does not claim to search all records or read your other applications. Recorded work remains available below the workspace routes.

## Read the state accurately

- The lattice follows the reported phase. It is an abstract representation, not a GPU meter, reasoning trace or proof of consciousness. It has no idle animation; activity opacity is used only for actual reported work/playback/recording/transcription, while the command view is visible. Reduced-motion settings disable it.
- Installed model availability does not mean that model is loaded into GPU memory. No token-rate, GPU load or fabricated agent activity is displayed.
- Microphone state comes from the actual voice snapshot. An active wake-once conversation is identified as awake; suppressed, starting and pending voice states remain distinct. This interface does not enable listening.
- Public web configuration and recent verification remain distinct. Web off describes Ariadne's reading control, not the computer's physical network adapter or a firewall guarantee.
- When the server becomes unreachable, observed work is marked last confirmed. Locked views clear private mission identity and cannot route into a remembered mission.

## Review an action

The decision readout opens the waiting mission. Its dossier shows the directive, response, execution evidence and complete approval arguments. The review shortcut waits for the dossier's first-render positioning, reveals the approval area and focuses its first action. A late callback cannot steal focus after locking, changing views or selecting another mission.

Existing per-action approval fingerprints, scopes, Approve once and Reject controls are unchanged. Global autonomy pause, microphone stop and browser lock remain separate controls. Locking the browser is not microphone stop.

## Accessibility and operating cost

The existing pairing boundary, initially inert application shell, closed-directory isolation, skip link, labels and keyboard behavior are retained. Small-screen status controls have 44-pixel targets. The directory closes with Escape and returns focus. All new data text uses the existing text-only renderer.

There are no new polling loops, model calls, external fonts, visual dependencies or continuously running canvas effects. Existing status reads drive the interface; voice snapshot changes update its derived presentation immediately. Energy and latency savings have not been measured.

## Verification scope

177 deterministic contract/snapshot/WSGI assertions, eight component UI tests and two syntax checks passed for this change. Browser review covered desktop 1440 by 900, tablet 768 by 1024 and phones 390 by 844 and 320 by 800, including no horizontal overflow, a visible directive action, directory focus return, workspace routing, locked privacy and a synthetic approval dossier. The approval reveal was observed with both actions inside the desktop viewport. Reduced-motion and one-page print protections were inspected in the CSS cascade; physical print pagination, screen-reader certification and actual 200-percent browser zoom were not asserted.

Screenshots and synthetic sample missions are private test evidence. No sample mission, model execution, voice capture, owner setting or data migration is part of this visual update. Reload the local interface to load the new assets; a server restart is not required.
