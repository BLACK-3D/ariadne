# Ariadne local wake word

Wake listening is an explicit session, started and stopped by the paired owner UI. Nothing starts recording merely because a server is installed or a page is opened. Say **“Ariadne, report the readiness status.”** in one utterance, or say **“Ariadne”** on its own. In PC mode, when idle and a local speaker callback is available, Ariadne replies **“Listening.”** without an LLM call. The microphone is suppressed during that acknowledgement and for a short 0.4-second playback tail, then a fresh twelve-second window opens for one command. A combined wake word and command needs no acknowledgement. **“Ariadne, stop listening”** ends the session without an LLM call. “Cancel” or “never mind” closes an opened command window; it does not undo or cancel a mission already submitted.

PC mode uses the default Windows waveform input at mono PCM16 16 kHz. Four 200 ms memory buffers feed the already provisioned Sherpa streaming recognizer, with two CPU inference threads. One recognizer is retained for the session; model weights are checked against the local pinned profile before use. Audio and unrelated ambient transcripts are not saved. A recognized, wake-prefixed command becomes a normal recorded mission. No LLM is queried while waiting for speech. Continuous ASR still consumes CPU and energy; idle power has not been measured.

Sessions default to eight hours. The owner can explicitly select **until stopped** for continuous operation; that mode has no session-expiry timer and requires no periodic manual renewal. The manager itself never starts a microphone on construction. A server may separately save the owner's explicit **resume PC listening when Ariadne starts** preference and then start an until-stopped session after launch; the default is no automatic listening. Stopping listening in the UI should also disable that saved startup preference. The native worker is limited to two GiB of memory and one process; these resource limits are not a security sandbox. Python network and child-process audit denials are applied after initializing the local recognizer. There are no model downloads or cloud speech calls.

Speech does not establish identity. Anyone or anything audible to the enabled microphone can attempt a wake-prefixed command. The mission dispatcher retains existing tool restrictions, approval requirements, maximum steps, paused-state checks and uncertain-result handling. A new spoken mission is refused while a previous spoken mission remains active; commands are not silently queued behind it. Completed, stopped and approval-waiting missions can receive a local spoken response when the server supplies its blocking speech callback. The listener discards input while that response plays, then for a two-second tail. Bare-word acknowledgement uses the shorter 0.4-second tail so an owner can respond promptly; physical echo behavior remains unqualified. Only one acknowledgement can be active in a session. An old acknowledgement cannot reopen a stopped or replacement session, and a failed acknowledgement stops capture with a visible audio-output error. This is suppression, not acoustic echo cancellation. Other applications' audio and room noise have not been qualified.

## Integration

`WakeService(settings, submit, *, blocked=None, get_run=None, speak=None, on_spoken_stop=None)` in `ariadne/wake.py` owns the session. `submit(command)` must return the normal queued run dictionary, `blocked()` checks pause/busy policy, `get_run(id)` returns current run state, and `speak(text)` blocks until actual playback completes. The optional `on_spoken_stop()` callback saves the owner's disabled startup preference only after a spoken stop has already stopped capture. A failed preference write leaves capture stopped and reports the uncertainty; it never retries a mission or claims that the preference was saved. Server shutdown, errors and expiry do not invoke this callback. `windows_speak_response` implements bounded local Windows SAPI playback through a fixed PowerShell command with text passed as JSON on stdin. It does not interpolate recognized text into executable code.

The authenticated UI calls `start(mode="pc", session_hours=8)`, `stop()` and `status()`. Passing `session_hours=None` explicitly selects until-stopped operation; status then reports `session_limit_hours: null`. Duration values are strictly either integer `8` or null; booleans, strings, floats and other durations are rejected. The fixed worker receives `--session-seconds 28800` or `--session-seconds 0`, respectively. Switching an active session's device or duration requires stopping it first. A separate browser adapter can submit **final** local-ASR utterances with `accept(text, source="browser", lease=current_lease, sequence=increasing_integer)` after `start("browser")`. This transport and gate are implemented; continuous browser capture needs a UI adapter. Native browser speech recognition is not used because a browser may route it through an online service. Lease, source and sequence checks prevent old-tab replay. They do not authenticate a voice.

Status intentionally exposes only coarse state and the submitted run ID. It contains no ambient transcript. Use `suppress(seconds)` to clear the command window and suppress PC recognition around separately generated UI speech. The regular push-to-talk workflow remains available separately.

## Qualification

Run `runtime\python\python.exe -I -B scripts\qualify_wake.py` from the box folder. This generates a known synthetic command, resamples it to PCM16 16 kHz, invokes the actual isolated streaming worker, and checks that the wake gate returns a readiness command. It never opens or records a microphone. The receipt is `data/wake-qualification/result.json`.

On this PC, the 2026-10-28 qualification recognized **“ARIADNE REPORT THE READINESS STATUS”** and routed the expected command. The finite ASR fixture took 0.283 seconds; speech generation plus probes and recognition took 4.393 seconds. These timings concern one known sample, not ambient power, human speech accuracy or a general throughput benchmark. A read-only device enumeration found one Windows waveform input. **Live microphone capture, human pronunciation, long-running stability, false-wake rate and acoustic playback suppression still require an owner microphone trial.** The Windows speech probe needs normal desktop registry access; a restricted coding sandbox's child speech process may lack it.

The wake tests check prefix boundaries, bounded windows, cancellation, explicit stop, replay suppression, lease/source/sequence checks, pause and busy rejection, independent timed expiry, uncertain dispatch, playback suppression, approval notices followed by an approved mission's final response, command-injection separation, and native PCM buffer lifetime against a fake WinMM. They use no live microphone.

## Primary references reviewed

- [Sherpa streaming recognition examples and API](https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/online-decode-files.py) describe the local streaming decoder pattern reused here.
- [Sherpa customized keyword spotting](https://k2-fsa.github.io/sherpa/onnx/kws/index.html) documents a smaller dedicated keyword decoder. This implementation reuses the existing ASR assets with an exact transcript gate; it does **not** claim that a dedicated “Ariadne” acoustic detector has been trained or provisioned.
- [Microsoft waveInOpen](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-waveinopen) specifies waveform input setup and the mapper device.
- [Microsoft waveInAddBuffer](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-waveinaddbuffer) specifies prepared buffers and the `WHDR_DONE` completion flag.
